# PRD：每日记录（Daily Record）

## Problem Statement

用户需要一个应用来记录「每天做了什么」，并追踪「连续完成记录」的天数。核心约束是**必须每天记录**：没完成当天的记录，就不能进入下一天的记录页；一旦某天漏掉，唯一的出路是清除连续天数、重新开始。用户需要一个把「每天记录」从意愿变成强制机制的可靠工具。

## Solution

一个 Android 原生应用，每一天对应一个「记录页」。用户在当天的页上（可选地）写若干条短条目，然后点「完成今天」。每天凌晨 1 点（设备本地时间），当天的页被冻结成只读历史，系统据此解锁或锁死下一天：完成了解锁，没完成就断链锁死，只能「清除连续天数、重新开始」（历史保留为只读）。

## User Stories

1. 作为用户，我希望打开应用直接落在「今天的记录页」，这样我能零摩擦地开始记录。
2. 作为用户，我希望在今天的页上添加一条「做了什么」的短条目，这样我能记下当天的事。
3. 作为用户，我希望在当天内编辑已写的条目，这样我能修正错别字或补充内容。
4. 作为用户，我希望在当天内删除某条条目，这样我能去掉写错的内容。
5. 作为用户，我希望点「完成今天」按钮把今天标记为完成，这样今天的记录被认定完成。
6. 作为用户，我希望即使一条条目都没写也能点「完成今天」，这样「今天没做什么特别的事」也能算完成。
7. 作为用户，我希望在当天内能撤销「完成今天」，这样我误点后能反悔。
8. 作为用户，我希望在应用顶部始终看到「连续天数」，这样我能一眼看到自己的 streak。
9. 作为用户，我希望凌晨 1 点过后今天这一页变成只读，这样历史不会被误改。
10. 作为用户，我希望只有在前一天「完成」时，今天的页才解锁，这样规则被强制执行。
11. 作为用户，我希望不能提前写未来某天的页，这样我不能「刷」连续天数。
12. 作为用户，我希望不能补写/补完成已冻结的过去某天，这样「必须每天记录」才有约束力。
13. 作为用户，当我某天没完成时，我希望看到「已断链」的明确状态，这样我知道链断了。
14. 作为用户，断链后我希望有一个「清除连续天数、重新开始」的入口，这样我能从今天重新起链。
15. 作为用户，我希望重置时连续天数归零、从今天重新计，而历史条目保留为只读，这样我不丢回忆又能重来。
16. 作为用户，我希望重置操作有确认提示，这样我不会手滑清零。
17. 作为用户，我希望重置按钮只在断链时出现，平时藏起来，这样避免误触。
18. 作为用户，我希望有一个日历式的历史视图，这样我能回看过去哪些天完成、哪天断链。
19. 作为用户，我希望点历史里的某一天能看到那天的只读条目详情，这样我能回顾过去。
20. 作为用户，我希望在凌晨 1 点冻结前收到一条「最后提醒」，这样我能在断链前补救。
21. 作为用户，我希望「最后提醒」的时间可以调整，这样它能符合我的作息。
22. 作为用户，我希望把数据导出成一个文件（JSON），这样我能备份到网盘或电脑以防丢。
23. 作为用户，我希望能从导出的文件导入恢复数据，这样换手机后能找回历史。
24. 作为用户，我希望应用完全离线可用，这样没有网络也能记录。
25. 作为用户，我希望「今天」按我设备的本地时区计算，这样记录跟着我的实际生活走。
26. 作为用户，我希望完成今天后主页能明确显示「今天已完成」，这样我知道当前状态。
27. 作为用户，我希望首次启动时连续天数为 0、直接打开今天的空页，这样我能立刻开始。

## Implementation Decisions

- **平台与技术栈**：Android 原生，Kotlin + Jetpack Compose。
- **分层架构**：抽出独立的**纯 Kotlin 领域引擎**（零 Android 依赖）承载全部规则；Room 负责持久化；Compose UI 只做展示与转发，不承载规则。
- **领域引擎职责**：给定「当前时间 + 时区 + 已完成天数集合」，计算某天是否冻结、是否解锁、当前连续天数、是否断链、重置后的状态。
- **一天边界**：日期 D 的记录页在 D+1 当天凌晨 1 点（设备本地时区）冻结并做解锁判定。凌晨 1 点是「一天」的分界。
- **严格锁定**：不允许提前写未来、不允许补写过去、没有宽限期。漏一天即断链，唯一出路是重置（见 ADR-0001）。
- **完成语义**：点「完成今天」即完成，不要求有条目（空页可完成）；当天内可撤销，跨天冻结后不可撤销。
- **连续天数**：从最近一天起、连续「完成」的天数，运行时由已完成天数推导，不单独存储；断链时显示断链前达到的值并标记为断链（红色），不再增长。
- **重置语义**：连续天数归零、从今天重新起链；历史条目保留为只读，不删除。
- **存储**：本地 Room 数据库，无云端同步；提供手动 JSON 导出/导入作为备份。
- **数据模型**：`Day`（日期为主键，含可空的完成时间戳）、`Entry`（文本、创建时间、所属日期、排序），连续天数与冻结状态均为派生计算，不落库。
- **提醒**：仅保留「边界前最后提醒」（默认凌晨 0:30，可调），用 WorkManager 调度系统通知。
- **界面结构**：主页 = 今天的记录页（顶部 streak 数字 + 条目列表 + 「完成今天」按钮）；历史用日历视图；重置按钮只在断链状态出现。

## Testing Decisions

- **只测外部行为，不测实现细节**：测试描述「给定输入，期望什么状态」，不依赖引擎内部怎么实现。
- **领域引擎是首要测试目标**：用纯单元测试穷举边界——1 点边界两侧、跨时区、连续/断链、漏一天、重置前后、空页完成、撤销完成。
- **数据层**：用内存 Room 测试 DAO 的增删改查与唯一性约束（一天一条 Day）。
- **UI**：保持薄，规则不在 UI，初期不做 UI 自动化测试。
- **先例**：全新项目，无既有测试可参照。

## Out of Scope

- 云端同步、账号系统、多设备。
- iOS / Web / Windows 版本。
- 固定习惯清单（预定义任务勾选）。
- 长文日记、富文本、图片附件。
- 社交、分享、排行榜。
- 编辑已冻结的历史（这是刻意的设计，非遗漏）。
- 跨时区旅行的复杂处理（作为已接受的边缘情况）。
